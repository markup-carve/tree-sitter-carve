===============================================================================
A tab after the fence opens no admonition
;; The colon fence has ONE separator slot and it is a MARKER SEPARATOR
;; (grammar.ebnf PART 7, normative since markup-carve/carve#886): the token
;; after it selects which of the four blocks the line opens, so it is
;; spelled `space` and a tab never satisfies it. `:::` + TAB + `note` is
;; therefore the same paragraph `:::note` is, and the trailing `:::` is
;; text with it because a malformed fence leaves the paragraph expecting a
;; closer (PART 9 §12).
;;
;; If the tab in the input below ever degrades to a SPACE, this case fails
;; loudly rather than rotting: `::: note` opens a div and the expected tree
;; here says paragraph. That asymmetry is why the four separator shapes can
;; live in a fixture file at all, where the PADDING shapes cannot - a tab
;; degrading to a space there keeps the same tree and stops testing
;; anything, so they are pinned in `bindings/rust/lib.rs` instead.
===============================================================================
:::	note
body
:::

  (paragraph))
